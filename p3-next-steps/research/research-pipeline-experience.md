# Research: Personal 3D Pipeline Experience

**Source type:** Lived experience — not a document or article

**What this is:** Direct experience working in 3D modeling for game development — moving models between 3ds Max, ZBrush, Unity, and Unreal Engine over time. This experience is the primary source for the problem the tool is solving.

**What I took from it:** The failure modes the tool addresses — broken imports, axis mismatches, scale errors, inverted normals — are things I have encountered repeatedly in my own pipeline. The systems map actors and feedback loops reflect patterns I recognized from practice, not from documentation. The peer testing outcome (the tool was useful) was consistent with this — the problem it solves is real and the use case is specific.

**Note:** This counts as research. The problem domain knowledge behind this project came from doing the work, not reading about it.
